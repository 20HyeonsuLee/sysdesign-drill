# 설계 문제 유형과 문제 은행

| 항목 | 값 |
|---|---|
| 상태 | 2026-10-21 |
| 함께 읽을 문서 | [PRD](PRD.md) N14, N15(숙달은 유형 단위, 유형마다 도메인이 다른 문제), [ARD](ARD.md) |

- 유형은 도메인이 아니라 **지켜야 할 규칙과 그 규칙을 깨는 장애의 조합**으로 나눈다. 공연 좌석 예매와 숙소 객실 예약은 도메인이 달라도 같은 유형일 수 있다.
- 유형 이름은 문제나 실패 현상으로 짓는다. 해법 이름은 쓰지 않는다.
- 모범 답과 해설은 이 문서에 쓰지 않는다.

## 1. 조사 방법

- 해외 정전 목록: Alex Xu System Design Interview 1, 2권, system-design-primer, Grokking(DesignGurus 원판, Educative 현행판), Hello Interview.
- 한국: 기업 기술블로그(배민, 토스, 카카오페이, 쿠팡, 올리브영, 당근 등)에서 반복되는 설계 주제. 한국 면접 질문 저장소 4곳은 CS 개념 질문 모음이라 설계 문제 목록이 없었다.
- 모은 문제를 규칙과 장애가 같은 것끼리 묶고, 정합성, 트래픽, 데이터, 식별자 관점으로 빠짐을 점검했다.

## 2. 채점 형태

| 기호 | 뜻 |
|---|---|
| A | 흐름 채점 가능. 실행 순서와 장애를 펼치면 맞고 틀림이 갈린다 |
| B | 수치와 객관식이 중심이다. 흐름 채점은 일부 측면만 가능하다 |
| C | 범위 밖. 구성도나 자료구조 선택이 핵심이라 이 형식으로 채점할 수 없다 |

## 3. 유형 표

### 3.1 정합성

| 번호 | 유형 | 지키는 규칙 | 깨는 장애 | 채점 | 문제(단계) |
|---|---|---|---|---|---|
| C1 | 한정 수량 초과 할당 | 할당 합은 총량을 넘지 않는다. 단위 자원은 한 번에 한 주인 | 동시 요청, 수량과 발급 기록 사이 다운, 두 저장소 한쪽만 반영 | A | 공연 좌석 예매(L1), 선착순 쿠폰 발급(L1, L2) |
| C2 | 동시 수정 중 갱신 유실 | 수락된 변경은 모두 결과에 남는다. 카운터는 증감의 합과 같다 | 둘 다 같은 옛 값을 읽고 각자 고쳐 쓴다 | A | 계좌 이체(L1), 게시글 좋아요(L1) |
| C3 | 없음을 확인하고 만드는 사이 중복 생성 | 같은 키의 기록은 하나뿐이다 | 둘 다 "아직 없음"을 확인한 뒤 각자 만든다 | A | 게시글 좋아요(L2), 선착순 쿠폰 발급(L1) |
| C4 | 여러 행 함께 바꾸기의 합계 깨짐과 교착 | 함께 바뀔 행은 모두 반영되거나 모두 안 된다. 합계 보존. 서로 기다리다 멈추지 않는다 | 첫 행만 바뀐 뒤 다운, 반대 방향 동시 처리 | A | 계좌 이체(L2) |
| C5 | 외부 호출 결과 모름 | 외부에서 일어난 일과 내 기록은 결국 같아진다. 같은 건을 두 번 청구하지 않는다 | 외부 타임아웃(실제로는 처리됨 또는 안 됨), 외부 응답 직후 다운 | A | 공연 좌석 예매(L2), 페이 머니 충전(L2) |
| C6 | 같은 요청 반복으로 이중 처리 | 사용자의 의도 하나는 효과 하나로만 남는다. 다시 보내면 처음과 같은 결과 | 버튼 연타, 응답 유실 뒤 재시도, 처리 중 다운 뒤 재시도 | A | 페이 머니 충전(L1) |
| C7 | 상태 변경과 전파 불일치 | 확정된 변경은 하류에 빠짐없이 전해진다. 롤백된 변경은 전해지지 않는다 | 확정 직후 전파 전 다운, 전파 실패나 결과 모름, 확정 전 전파 뒤 롤백 | A | 회원가입 뒤 계좌 자동 개설(L1) |
| C8 | 여러 서비스 단계 중간 실패 후 앞 단계 잔존 | 중간에 실패하면 끝난 앞 단계는 결국 되돌려진다. 되돌림이 두 번 반영되지 않는다 | 뒷 단계 실패, 되돌림 요청의 실패나 결과 모름, 되돌림 도중 다운 | A | 쇼핑몰 주문 접수(L1, L2) |
| C9 | 메시지 재전달로 이중 반영 | 같은 메시지가 여러 번 와도 효과는 한 번. 메시지는 빠지지 않는다 | 처리 뒤 소비 확인 전 다운, 생산 쪽 재발행 | A | 회원가입 뒤 계좌 자동 개설(L2) |
| C10 | 이벤트 순서 역전으로 최신 상태 덮임 | 최종 상태는 마지막으로 일어난 일과 같다 | 병렬 소비, 재시도로 뒤로 밀림 | A | 택배 배송 상태 추적(L1, L2) |
| C11 | 파생 사본에 낡은 값 고착 | 원본이 바뀌면 사본도 같아진다. 낡은 값이 최신 값을 덮어 남지 않는다 | 사본 채우기 경합, 원본 갱신 뒤 사본 처리 전 다운 | A | 상품 가격 캐시(L1) |
| C12 | 복제 지연 사본으로 내린 잘못된 판단 | 방금 쓴 값을 다시 읽으면 그 값을 본다. 옛 값으로 판단하지 않는다 | 복제 지연 | A | 비밀번호 변경 직후 로그인(L1, L2) |
| C13 | 배타적 상태 전이가 둘 다 일어남 | 같은 상태에서 갈라지는 두 전이 중 하나만 일어난다. 점유는 기한이 지나면 결국 풀린다 | 만료 처리와 확정 요청의 동시 실행, 만료 처리기 다운 | A | 숙소 예약 결제 대기 점유(L1, L2) |
| C14 | 예약 작업 누락 또는 중복 실행 | 시각이 지난 작업은 결국 한 번 실행된다. 두 번 실행되지 않는다 | 실행자 여러 대가 같은 작업을 집음, 실행 도중 다운 뒤 재실행 | A | 구독 정기 결제(L1, L2) |
| C15 | 연결 끊김 사이 실시간 전달 유실과 중복 표시 | 보낸 메시지는 다시 접속하면 결국 받는다. 같은 메시지가 두 번 표시되지 않는다 | 수신자 연결 끊김, 전송 확인 유실 뒤 재전송 | A | 중고거래 1:1 채팅(L1, L2) |

### 3.2 트래픽

| 번호 | 유형 | 지키는 규칙 | 깨는 장애 | 채점 | 문제(단계) |
|---|---|---|---|---|---|
| R1 | 순간 폭주로 처리 자원 고갈 | 수락한 요청은 끝까지 처리된다. 처리 못 할 요청이 처리할 요청을 막지 않는다 | 오픈 시각 폭주, 스레드와 커넥션 고갈 | B | 공연 좌석 예매(L3), 선착순 쿠폰 발급(L3), 수강신청 대기열(L3) |
| R2 | 호출 한도 초과 통과 | 키마다 구간 안 허용 수보다 많이 통과하지 않는다 | 여러 서버가 같은 키를 동시에 셈, 구간 경계, 셈 저장소 장애 | B | 오픈 API 호출 한도(L1~L4) |
| R3 | 느린 의존성이 전체 응답을 붙잡음 | 하위 시스템 하나가 느려도 무관한 기능은 제때 응답한다 | 외부 응답 지연, 기다리는 동안 자원 점유, 재시도 폭주 | B | 항공권 가격 비교(L1~L4), 공연 좌석 예매(L4) |
| R4 | 대량 외부 발송의 누락, 중복, 한도 위반 | 각 건은 정확히 한 번 발송된다. 상대 한도를 넘지 않는다 | 발송 도중 다운 뒤 재시작, 대행사 결과 모름, 작업자 둘 | A | 마케팅 메시지 대량 발송(L1, L2) |
| R5 | 대기 순번 역전과 입장 인원 초과 | 동시에 들어온 인원은 정한 수를 넘지 않는다. 나간 자리는 다음 사람에게 넘어간다 | 폭주, 알리지 않은 이탈, 대기열 처리 다운 | A | 수강신청 대기열(L1, L2) |
| R6 | 캐시 미스 순간 원본 쏠림 | 캐시가 비어도 원본으로 가는 동시 요청 수는 원본이 견디는 수를 넘지 않는다 | 인기 키 만료 순간 동시 미스 | A | 상품 가격 캐시(L2) |
| R7 | 한 번의 쓰기가 수많은 수신자에게 퍼지는 비용 폭발 | 글은 모든 팔로워에게 보인다. 지운 글은 보이지 않는다 | 퍼뜨리는 도중 다운, 삭제와 퍼뜨리기의 경합, 팔로워 수 극단 | B | SNS 팔로워 피드(L1~L3) |

### 3.3 데이터와 식별자

| 번호 | 유형 | 지키는 규칙 | 깨는 장애 | 채점 | 문제(단계) |
|---|---|---|---|---|---|
| D1 | 대량 배치 중간 실패 후 재실행 시 누락과 이중 처리 | 대상 건마다 정확히 한 번 처리된다. 재실행해도 결과가 같다 | 배치 중간 다운, 같은 배치 두 번 기동, 늦게 들어온 원천 데이터 | A | 카드 가맹점 일별 정산(L1, L2) |
| D2 | 늦거나 중복된 이벤트로 집계 구간 틀어짐 | 각 이벤트는 정확히 한 번, 일어난 시각의 구간에 반영된다 | 중복 이벤트, 늦은 도착, 집계기 다운 | A | 광고 클릭 과금 집계(L1, L2) |
| D3 | 데이터 분할 쏠림과 재분배 비용 | 모든 키는 정해진 한 곳에서 찾는다. 조각의 부하가 비슷하다 | 키 쏠림, 조각 추가와 재분배 | B | 결제 원장 DB 이관(L3~L5) |
| D4 | 이관 중 들어온 쓰기 유실 | 이관하는 동안 들어온 쓰기도 새 저장소에 빠짐없이 반영된다 | 복사 도중 갱신, 두 곳 쓰기 중 한쪽 실패 | A | 결제 원장 DB 이관(L1, L2) |
| D5 | 깊은 페이지 조회 비용과 순회 중 누락 | 몇 번째 페이지든 응답 시간이 비슷하다. 넘기는 동안 항목이 빠지거나 겹치지 않는다 | 깊은 페이지, 순회 중 삽입 | B | 게시글 좋아요(L5) |
| N1 | 분산 발급 식별자 충돌 | 발급된 식별자는 전체에서 하나뿐이다 | 여러 서버 동시 발급, 짧은 코드끼리 충돌 | A | 단축 URL 발급(L1, L2) |

### 3.4 범위 밖 (C)

위치 기반 근접 탐색, 텍스트 검색과 순위, 대용량 파일과 미디어 저장, 실시간 공동 편집 병합, 웹 수집, 체결과 차례 엔진, 관측 데이터 수집, 객체 설계, 기반 시스템 자체 설계. 구성도나 자료구조 선택이 핵심이라 문제로 내지 않는다([PRD](PRD.md) 9절). 기반 시스템(DB, 브로커, 캐시)의 내부 동작은 각 문제의 L5에서 묻는다.

## 4. 빠짐 점검

| 관점 | 유형 |
|---|---|
| 단일 자원 동시성 | C1, C2, C3 |
| 여러 자원 원자성 | C4(한 저장소), C7, C8(저장소를 넘음) |
| 외부 결과 모름 | C5(단건), R4(대량), C8(되돌림) |
| 중복 요청 | C6(클라이언트가 다시 보냄), C9(브로커가 다시 보냄) |
| 메시지 순서 | C10 |
| 파생 데이터 | C11(캐시), C12(복제본), R6(캐시 미스), C2(카운터), D2(집계) |
| 시간 기반 상태 | C13(만료), C14(예약 실행) |
| 과부하와 장애 전파 | R1, R2, R3 |
| 쏠림 | 독립 유형으로 두지 않았다. 다른 규칙과 묶일 때만 위반이 생겨서 각 문제의 L3에서 다룬다 |
| 팬아웃, 대기열 | R7, C15, R5 |
| 대량 데이터 | D1, D2, D3, D4, D5 |
| 식별자 | N1 |

- 시계 차이, 멈췄다 깨어난 처리자는 독립 유형이 아니라 장애 종류로 넣었다.
- 경계가 흐린 쌍: C6과 C9(같은 규칙, 다시 보내는 쪽만 다름), R4와 D1(같은 "각 건 정확히 한 번", 외부 발송 여부만 다름). 숙달 집계에서 같은 실패 유형 태그(중복 요청, 중복 전달, 재실행)로 이어진다.
